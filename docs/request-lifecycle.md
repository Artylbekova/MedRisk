# Жизненный цикл UC3: оценка риска

## 1. Действие пользователя
Врач открывает доступную карточку и нажимает «Оценить риск»; React отправляет запрос.

## 2. DNS
Браузер определяет IP-адрес api.medrisk.example (условный домен учебного проекта).

## 3. TCP/TLS
Браузер устанавливает защищённое HTTPS-соединение с сервером.

## 4. HTTP-запрос
POST /api/patients/42/assessments; Authorization: Bearer <token>; Content-Type: application/json; тело: {"observationIds":[101,102,103]}. Идентификатор врача берётся из токена.

## 5. Приём
NestJS Controller принимает запрос и передаёт его на проверку.

## 6. Backend
Auth Guard проверяет токен; RBAC и назначение доступа — право врача на пациента 42; Service валидирует показатели, вызывает Inference API и готовит запись.

## 7. База данных
Prisma читает назначения и показатели из PostgreSQL; после успешного расчёта сохраняет RiskAssessment с версией модели и AuditEvent в транзакции.

## 8. Ответ
201 Created; JSON: {"id":501,"patientId":42,"riskScore":0.24,"riskLevel":"moderate","modelVersion":"demo-0.1","advisoryOnly":true}. При отказе — 403, при недоступности модели — 503; оценка не выдумывается.

## 9. Интерфейс
React показывает предварительный риск, предупреждение об ограничениях и ссылку на историю; при ошибке — понятное сообщение.
