# Журнал проверки и работы с ИИ

## Проверенные технические риски и способы исправления
1. **CORS**: браузер блокирует запрос с другого origin. API разрешает `http://localhost:5173`; Vite закреплён на порту 5173.
2. **HTTP 204**: вызов `response.json()` вызывает ошибку. Удаление обрабатывается отдельной веткой без JSON.
3. **Невалидный JSON**: структура ответа может отличаться от TypeScript-типа. Все сетевые данные проверяются type guards.
4. **Запрос после размонтирования**: может обновлять устаревший экран. Хук использует `AbortController` и очистку `useEffect`.
5. **Строковый ID маршрута**: `useParams()` возвращает строку. ID преобразуется в число и проверяется.
6. **Неверный ввод чисел**: HTML `input` возвращает строку. В форме вызывается `Number()` и серверная проверка диапазонов.

Это перечень проектных проверок, **не журнал реально воспроизведённых ошибок**. Для отчёта запишите собственные сообщения и скриншоты при запуске.

## Использование ИИ
- Запрос: «Создай учебный React + TypeScript клиент для MedRisk с REST CRUD и type guards». Ответ: архитектура и код приложения. Проверка: выполнить `npm run check`, `npm run build`, ручные сценарии CRUD; зафиксировать результаты.
- Запрос: «Как корректно обрабатывать 204, ошибки сети и отмену запросов?». Ответ: отдельный обработчик DELETE, `Result<T>`, `AbortController`. Проверка: отключить API, удалить запись, перейти между страницами; записать фактическое поведение.

При защите объясните код и самостоятельно внесите небольшое изменение.
